2. 在面板创建入站和客户端

  1. 进入 3x-ui 的「入站」页面，创建并启用入站。
  2. 记下入站端口，例如 44584。
  3. 在入站中添加客户端，确保客户端未过期、未禁用。
  4. Docker Compose、云安全组和防火墙都要放行该入站端口。

如果 Clash 测速显示 Timeout，且外网测试该端口返回 Connection refused，优先检查以下三项：

  1. docker-compose.yml 是否映射了节点端口。
  2. 入站是否已启用，Xray 是否正常运行。
  3. 云安全组、UFW 或其他防火墙是否放行 TCP 端口。

3. 配置 Clash/Mihomo 订阅

进入「面板设置 → 订阅设置」：

  1. 启用订阅服务。
  2. 确认订阅端口为 2096。
  3. 进入「Clash / Mihomo」页，启用 Clash / Mihomo 订阅。
  4. 客户端复制 Clash/Mihomo 格式的订阅地址。

4. 由 3x-ui 下发默认分流规则

机场订阅通常会下发“节点 + 代理组 + 路由规则”。3x-ui 也可以在订阅中下发规则：

  1. 进入「面板设置 → 订阅设置 → Clash / Mihomo」。
  2. 打开「启用路由」。
  3. 在「全局路由规则」填入规则。
  4. 保存后，在 Clash Verge 更新订阅。

这里的规则会被添加到 YAML 订阅开头、默认 MATCH,PROXY 之前。因此最后放入 MATCH,DIRECT，即可实现“指定网站走代理，其余全部直连”。

PROXY 必须和订阅中的代理组名称一致。使用默认 3x-ui Clash/Mihomo 模板时，通常就是 PROXY。如果你改过代理组名称，请同步修改规则中的目标名称。

5. Clash Verge 使用方式

  1. 导入 /clash/客户端SubID 订阅地址。
  2. 在「代理」页的 PROXY 组中选择自己的节点，不要选 DIRECT。
  3. 顶部模式选择「规则」。
  4. 更新订阅后，面板配置的全局路由规则会同步到 Clash Verge。

6. 最短排错清单

现象 原因 处理
订阅导入提示 invalid yaml 使用了 /sub/ 改用 /clash/客户端SubID
Clash 节点测速超时 节点端口未映射或未放行 在 Compose、云安全组、系统防火墙同时开放入站端口
面板和订阅能打开，但节点连不上 仅映射了 2053、2096 追加节点端口，例如 44584:44584
所有流量都走代理 默认规则是 MATCH,PROXY 启用 Clash/Mihomo 路由并在最后添加 MATCH,DIRECT
指定网站没有走代理 规则放在 MATCH,DIRECT 后面，或 PROXY 组未选节点 把规则移动到 MATCH,DIRECT 前，并选择节点
